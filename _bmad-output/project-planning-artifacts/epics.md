# way2we - Epic Breakdown

## Overview

This document provides the complete epic and story breakdown for way2we, decomposing the requirements from the PRD, UX Design, and Architecture requirements into implementable stories.

## Requirements Inventory

### Functional Requirements

**账户与身份**
- FR1: 用户可以注册与登录账户
- FR2: 用户可以管理基础个人资料（头像、昵称）

**群组创建与设置**
- FR3: 用户可以创建群组
- FR4: 用户可以邀请成员加入群组
- FR5: 群组创建者可以设置群组基础配置
- FR6: 群组可以设置约定是否需要他人确认的默认值
- FR7: 群组可以设置兑换是否自动完成的默认值
- FR8: 群组可以设置兑换是否自动确认履约的默认值
- FR9: 群组配置可以被授权成员查看与修改

**规则与积分**
- FR10: 成员可以创建、编辑与停用约定规则（需具备权限）
- FR11: 成员可以创建、编辑与停用商品（兑换项）
- FR12: 成员完成约定后系统可产生积分变动
- FR13: 积分累积与余额对群组成员可见

**任务与确认**
- FR14: 成员可以标记约定完成
- FR15: 创建约定时可配置是否需要他人确认
- FR16: 成员可以确认或驳回他人完成约定的请求
- FR17: 具有授权的成员可以替他人完成约定，并指定完成者

**兑换与履约**
- FR19: 成员可以发起兑换请求
- FR20: 创建兑换时可配置是否自动完成兑换
- FR21: 创建兑换时可配置是否自动确认履约
- FR22: 兑换提供者可以完成或拒绝兑换
- FR23: 兑换发起者可以确认履约
- FR24: 兑换状态对相关成员可追踪

**权限控制**
- FR25: 群组支持角色与权限分级
- FR26: 群组创建者可以授权他人管理权限
- FR27: 可配置哪些成员允许创建/修改/删除约定
- FR28: 可配置哪些成员允许为他人执行约定
- FR29: 可配置哪些成员允许修改群组默认值
- FR30: 有权限的成员修改约定无需审核
- FR31: 无权限成员不可修改约定

**特殊事件**
- FR34: 具备权限的成员可以创建特殊事件为某用户加/减积分
- FR35: 特殊事件的创建权限可配置

**撤销与回退**
- FR36: 约定完成可被撤销并回退积分
- FR37: 兑换完成可被撤销并回退积分
- FR38: 特殊事件可被撤销并回退积分

**通知与提醒**
- FR39: 系统可发送待办事项通知（需要用户操作的事项）
- FR40: 系统可发送积分变化通知（自己和群组成员）
- FR41: 成员可配置通知偏好并查看通知历史

**记录与审计**
- FR42: 系统记录活动日志（约定、积分、兑换、特殊事件）
- FR43: 系统记录积分变更明细
- FR44: 系统记录规则/配置变更的审计日志

**内容与素材**
- FR45: 成员可以为商品设置封面图片
- FR46: 成员可以为约定设置封面图片

### NonFunctional Requirements

**性能 (Performance)**
- NFR1: 关键用户操作（创建约定、发起兑换、确认履约）响应时间 ≤ 2 秒
- NFR2: 推送通知从触发到送达的目标时间 ≤ 30 秒
- NFR3: 列表页（约定/兑换/活动记录）首屏加载时间 ≤ 2 秒

**可扩展性 (Scalability)**
- NFR4: 支持用户规模提升 10x 时，核心操作响应时间不劣化超过 10%
- NFR5: 支持群组数量与成员数量增长，不影响核心链路稳定性
- NFR6: 具备水平扩展能力，避免单点瓶颈导致服务中断

**可用性 (Usability)**
- NFR7: 首次使用用户可在 5 分钟内完成创建约定并发起一次兑换
- NFR8: 权限相关配置有明确提示，避免误操作
- NFR9: 关键流程（创建约定、兑换）步骤清晰、可回退

**可靠性 (Reliability)**
- NFR10: 关键链路成功率 ≥ 99%（创建约定、完成约定、兑换成功）
- NFR11: 关键操作稳定可靠（无数据丢失、无异常回滚）

### Additional Requirements

**架构技术需求:**

1. **Starter 模版** (影响 Epic 1 Story 1):
   - Flutter 客户端：使用 Very Good Core 模版初始化
   - Go 服务端：使用 Standard Go Project Layout (模块化单体)

2. **技术栈约束:**
   - Flutter + BLoC 状态管理
   - Go + Echo + Ent + PostgreSQL
   - JWT 认证中心 + 多供应商适配 (SMS/Social)

3. **基础设施要求:**
   - 阿里云/腾讯云短信服务集成
   - 极光推送 (JPush) / 个推 (GeTui) 集成
   - 云存储（图片上传）

4. **API 与数据:**
   - RESTful + JSON (snake_case)
   - 积分一致性：TCC + 数据库本地事务
   - Ent Graph 处理 User-Group-Rule 关系

5. **命名与模式一致性:**
   - 数据库：复数 + snake_case (users, point_logs)
   - API JSON：snake_case
   - Flutter：Feature-First 目录结构

**UX 设计需求:**

1. **响应式设计:**
   - 仅支持手机竖屏（iPhone 14 / Android 主流机型）
   - 基准设计尺寸：390×844 pt

2. **无障碍 (Accessibility):**
   - WCAG 2.1 AA 级别
   - 色彩对比度 ≥ 4.5:1
   - 触控目标 ≥ 44×44 dp
   - 支持屏幕阅读器 (VoiceOver/TalkBack)
   - 尊重系统「减少动态效果」设置

3. **设计系统:**
   - 可主题化设计系统（2-3 套色彩主题）
   - 首套主题：Warm Orange (#f07c42)
   - 字体：Plus Jakarta Sans + 中文回退

4. **交互模式:**
   - 底部 4 Tab 导航（首页、约定、兑换、我的）
   - 横向滚动卡片布局
   - 即时反馈（积分变动动效）
   - 骨架屏加载态

5. **组件规格:**
   - AgreementCardCompact (260px 宽)
   - RewardCardCompact (200px 宽)
   - PointsCard (主题色渐变背景)
   - 统一的 StatusBadge 状态标签

## Epic List

## Epic 1: 项目基础与用户认证

用户可以注册账户、登录系统并管理个人资料（头像、昵称），建立系统基础架构。支持手机号和邮箱两种验证方式。

**FRs 覆盖:** FR1, FR2  
**技术要求:** Very Good Core (Flutter), Standard Go Project Layout, JWT 认证 + Mock 验证码 (Log/Magic)

### Story 1.1: 初始化项目基础设施

As a **开发团队**,
I want **使用标准模版初始化 Flutter 和 Go 项目**,
So that **我们有一个符合最佳实践的代码库基础来开始开发**.

**Acceptance Criteria:**

**Given** 开发环境已准备就绪  
**When** 执行项目初始化脚本  
**Then** Flutter 项目使用 Very Good Core 模版创建，包含 BLoC、Dio、国际化配置  
**And** Go 项目使用 Standard Layout 创建，包含 Echo + Ent + Viper 配置  
**And** PostgreSQL 数据库连接配置完成  
**And** 基础的 CI/CD 配置文件存在  
**And** 项目可以成功编译运行（空白欢迎页）

---

### Story 1.2: 多模式身份验证码发送 (Mock 模式)

As a **用户**,
I want **输入手机号或邮箱并获取验证码**,
So that **我可以验证我的身份来注册或登录**.

**Acceptance Criteria:**

**Given** 用户在登录/注册页面  
**When** 输入有效的手机号或邮箱地址并点击"获取验证码"  
**Then** 系统根据后端配置生成 6 位验证码  
**And** 将验证码输出至后端系统日志（DEBUG 模式可见）  
**And** 前端按钮显示 60 秒倒计时  
**And** 只要输入日志中的代码或预设的魔法代码（如 123456），校验即通过  

**Given** 后端配置为真实模式（未来扩展）  
**When** 请求验证码  
**Then** 通过 SmsProvider 或 EmailProvider 调用真实网关发送

---

### Story 1.3: 用户注册与设置密码

As a **新用户**,
I want **使用手机号或邮箱注册账户并设置密码**,
So that **我可以创建账户并使用密码登录**.

**Acceptance Criteria:**

**Given** 用户输入了手机号/邮箱且未注册  
**When** 输入正确的验证码（日志可见或魔法码）并提交  
**Then** 系统提示用户设置登录密码（6-20 位）  

**Given** 用户设置密码成功  
**When** 点击“完成注册”  
**Then** 系统创建 User + UserIdentity 记录  
**And** 密码经过 bcrypt 哈希后存储  
**And** 用户自动登录并跳转到设置昵称页面  

---

### Story 1.4: 用户密码登录

As a **已注册用户**,
I want **使用账号和密码登录**,
So that **我可以访问我的账户和数据**.

**Acceptance Criteria:**

**Given** 用户已注册  
**When** 输入账号（手机号/邮箱/用户名）+ 密码  
**Then** 系统根据输入格式智能识别账号类型  
**And** 查询 UserIdentity 并校验密码  
**And** 验证成功后签发 JWT Token  
**And** 跳转到首页  

**Given** 密码错误  
**When** 提交登录  
**Then** 显示“账号或密码错误”  

---

### Story 1.5: 个人资料管理

As a **用户**,
I want **设置和修改我的头像和昵称**,
So that **其他群组成员可以识别我**.

**Acceptance Criteria:**

**Given** 用户已登录  
**When** 进入个人资料页面  
**Then** 显示当前头像（默认为系统头像）和昵称  
**And** 可以点击头像进入编辑模式

**Given** 用户点击更换头像  
**When** 从相册选择图片  
**Then** 图片上传到云存储  
**And** 头像更新显示新图片  
**And** 显示成功提示

**Given** 用户修改昵称  
**When** 输入新昵称（1-20 个字符）并保存  
**Then** 昵称更新成功  
**And** 显示成功提示

**Given** 用户输入超过 20 个字符的昵称  
**When** 尝试保存  
**Then** 显示错误提示"昵称不能超过 20 个字符"

---

### Story 1.6: 登出与会话管理

As a **用户**,
I want **能够登出账户**,
So that **我可以保护账户安全或切换账户**.

**Acceptance Criteria:**

**Given** 用户已登录并在"我的"页面  
**When** 点击"退出登录"按钮  
**Then** 显示确认对话框"确定要退出登录吗？"  

**Given** 用户在确认对话框中  
**When** 点击"确定"  
**Then** 清除本地存储的 token 和用户数据  
**And** 跳转到登录页面  

**Given** 用户在确认对话框中  
**When** 点击"取消"  
**Then** 关闭对话框，保持当前页面

---

## Epic 2: 群组创建与成员管理

用户可以创建群组、邀请他人加入、配置群组默认设置、设置成员角色和权限。

**FRs 覆盖:** FR3-FR9, FR25-FR29  
**依赖:** Epic 1（需要已认证用户）

### Story 2.1: 创建群组

As a **用户**,
I want **创建一个新群组**,
So that **我可以与家人或伴侣开始使用积分兑换系统**.

**Acceptance Criteria:**

**Given** 用户已登录且没有加入任何群组  
**When** 点击"创建群组"按钮  
**Then** 显示创建群组表单  

**Given** 用户在创建群组表单中  
**When** 输入群组名称（1-30 字符）并提交  
**Then** 系统创建群组，用户成为群组创建者和管理员  
**And** 自动进入该群组的首页  

**Given** 用户已是某群组成员  
**When** 想创建新群组  
**Then** 可以在"我的"页面找到"创建新群组"入口

---

### Story 2.2: 生成与分享邀请链接

As a **群组管理员**,
I want **生成邀请码或链接**,
So that **我可以邀请其他人加入群组**.

**Acceptance Criteria:**

**Given** 用户是群组管理员  
**When** 进入群组设置页面点击"邀请成员"  
**Then** 显示 6 位字母数字邀请码  
**And** 显示"复制链接"和"分享"按钮  

**Given** 用户点击"分享"  
**When** 系统调用分享功能  
**Then** 可以通过微信/短信等方式分享邀请链接  

**Given** 邀请码已生成  
**When** 管理员点击"刷新邀请码"  
**Then** 旧邀请码失效，生成新的邀请码

---

### Story 2.3: 加入群组

As a **用户**,
I want **通过邀请码加入群组**,
So that **我可以与家人或伴侣共同使用积分系统**.

**Acceptance Criteria:**

**Given** 用户已登录但未在目标群组中  
**When** 输入有效的邀请码并提交  
**Then** 显示群组信息预览（名称、成员数）  
**And** 显示"确认加入"按钮  

**Given** 用户确认加入  
**When** 点击"确认加入"  
**Then** 用户成为群组成员（普通成员角色）  
**And** 自动切换到该群组首页  

**Given** 邀请码无效或已过期  
**When** 提交邀请码  
**Then** 显示错误提示"邀请码无效或已过期"

---

### Story 2.4: 查看群组列表与切换群组

As a **用户**,
I want **查看我加入的所有群组并在它们之间切换**,
So that **我可以管理不同的关系和积分系统**.

**Acceptance Criteria:**

**Given** 用户已加入多个群组  
**When** 点击首页顶部的群组名称/图标  
**Then** 显示群组列表抽屉或弹窗  
**And** 列表显示每个群组的名称、头像和成员数  
**And** 当前活动群组有明显标识  

**Given** 用户在群组列表中  
**When** 点击另一个群组  
**Then** 切换到该群组，首页显示该群组的数据  
**And** 本地保存选择，下次打开 App 自动进入该群组  

**Given** 用户只有一个群组  
**When** 打开群组切换界面  
**Then** 显示"创建新群组"和"加入群组"选项

---

### Story 2.5: 群组成员列表与角色管理

As a **群组管理员**,
I want **查看成员列表并设置成员角色**,
So that **我可以控制谁有管理权限**.

**Acceptance Criteria:**

**Given** 用户是群组管理员  
**When** 进入群组设置 > 成员管理  
**Then** 显示所有成员列表，包含头像、昵称、角色  
**And** 显示每个成员的加入时间  

**Given** 管理员查看成员详情  
**When** 点击某个成员  
**Then** 可以将该成员设为管理员或取消管理员身份  
**And** 可以进入权限设置页面为该成员分配具体权限  

**Given** 群组只有一个管理员  
**When** 尝试将自己降级为普通成员  
**Then** 显示错误提示"群组至少需要一名管理员"

---

### Story 2.6: 群组默认配置设置

As a **群组管理员**,
I want **设置群组的默认配置**,
So that **新创建的约定和商品自动使用这些默认值**.

**Acceptance Criteria:**

**Given** 用户是群组管理员  
**When** 进入群组设置 > 默认配置  
**Then** 显示可配置项：  
- 约定默认是否需确认  
- 兑换默认是否自动完成  
- 兑换默认是否自动确认履约  
- **提供者激励比例**（默认 0%，可设置 0-100%）  

**Given** 管理员修改默认配置  
**When** 切换开关并保存  
**Then** 配置保存成功  
**And** 新创建的约定/商品将使用新的默认值  
**And** 已存在的约定/商品不受影响

---

### Story 2.7: 成员权限分配

As a **群组管理员**,
I want **为成员分配具体权限**,
So that **我可以精细控制谁能做什么**.

**Acceptance Criteria:**

**Given** 用户是群组管理员  
**When** 进入成员详情 > 权限设置  
**Then** 显示可配置权限列表：创建约定、修改约定、删除约定、代他人完成约定、修改群组默认值、创建特殊事件、撤销记录  

**Given** 管理员修改成员权限  
**When** 勾选/取消权限并保存  
**Then** 权限立即生效

## Epic 10: 活动记录与审计

查看群组活动动态、成员积分变更明细，管理员可查看完整操作日志。

### Story 10.1: 首页群组活动动态

As a **群组成员**,

So that **我了解群组的最新动态**.

**Given** 用户在群组首页  
**When** 页面加载  
**Then** 显示群组所有成员的近期活动列表  
**And** 每条活动显示：头像、成员名、事件描述、时间、积分变动  

**Given** 活动类型包括  
**When** 查看活动列表  
**Then** 显示：完成约定、兑换商品、特殊事件、撤销操作

**Then** 新活动显示在列表顶部

### Story 10.2: 查看成员积分明细

As a **群组成员**,
I want **查看任何成员（包括自己）的积分变更记录**,
So that **我了解积分的来源和去向**.

**Acceptance Criteria:**

**Given** 用户点击首页积分卡片  
**When** 进入积分详情  
**Then** 默认显示自己的积分明细

### Story 10.3: 管理员操作日志

As a **群组管理员**,
I want **查看群组内所有人的操作日志**,
So that **我可以追踪重要操作和处理纠纷**.

**Acceptance Criteria:**

**Given** 用户是群组管理员  
**When** 进入群组设置 > 操作日志  
**Then** 显示所有成员的操作记录  
**And** 包含：操作人、操作类型、操作内容、操作对象、时间  

**Given** 管理员查看操作日志  
**When** 选择筛选条件（操作人、操作类型、时间范围）  
**Then** 列表按条件过滤  

**Given** 发生纠纷需要追溯  
**When** 查看操作日志  
**Then** 可以看到完整的操作历史（包括撤销记录）  

**Given** 用户不是管理员  
**When** 进入群组设置  
**Then** 不显示"操作日志"入口
