# 业务验收场景

状态：第一阶段验收基线已整理完成。此文档记录预期行为，执行验证在原型和实现阶段开展。

规则依据：[产品规则](rules.md)。主流程及状态：[核心流程与状态](flows-and-states.md)。各场景独立准备前提数据。

## 空间与成员

| 编号 | 前提与操作 | 预期结果 |
| --- | --- | --- |
| S01 | 甲在空间 A，另按加入规则加入空间 B | 同一账号拥有两份空间成员身份，余额和小卖部分别管理 |
| S02 | 空间 A 有甲、乙；丙接受邀请，只有甲同意 | 丙仍等待加入；乙也同意后，丙成为成员且初始余额为 0 |
| S03 | 甲、乙、丙为当前成员，甲查看乙的业务数据 | 可以查看该空间的约定、积分余额与明细、小卖部和购买记录 |
| S04 | 甲在空间 A 获得积分 | 只改变其在 A 的余额；在 B 购买时核验 B 的余额 |
| S05 | 甲主动退出空间 | 暂停查看和操作该空间，其他成员暂停为甲新增记分，甲的店铺暂停新购买；历史和余额保留 |
| S06 | 甲曾经退出，主动重新加入 | 直接恢复参与和保留的数据，店铺沿用原上下架设置，已取消购买保持取消结果 |
| S07 | 空间全部成员退出，随后某位历史成员返回 | 空间及全部数据仍在，历史成员可直接恢复参与 |
| S08 | 新人已接受邀请但未获全员同意，当前成员全部退出 | 新人保持等待；历史成员恢复参与后，按当前成员集合重新核验同意条件 |

## 约定与记分

| 编号 | 前提与操作 | 预期结果 |
| --- | --- | --- |
| A01 | 甲、乙、丙在同一空间；约定只适用于甲、乙 | 三人均可查看和修改；新增记分的涉及成员取自当前适用成员 |
| A02 | 甲完成两次同一条 +10 分约定，并分别记录 | 形成两条有效记分，甲总计获得 20 分；两次记录各有操作者和时间 |
| A03 | 丙为适用成员甲记录一次约定完成 | 记分立即生效；空间全体成员可查看完整记录 |
| A04 | 已有一条 +10 分记分；任意当前成员把约定改为 +20 分 | 旧记分保持 +10，新记分按 +20；约定修改记录可查询 |
| A05 | 成员余额 3 分，发生一条 −5 分记分 | 余额成为 −2 分，记录实际扣除的 5 分 |
| A06 | 任意当前成员撤销一条原值为 +10 分的记分，约定现值为 +20 分 | 按原值回退 10 分；原记录标记已撤销，显示原记分及撤销操作者、时间、分值 |
| A07 | 成员当前余额 3 分，撤销其先前的 +10 分记分 | 当前余额成为 −7 分，回退依据原记分完整执行 |
| A08 | 对同一条已经撤销的记分再次提交撤销 | 保持已经完成的一次回退及清晰的撤销记录 |
| A09 | 任意当前成员停用约定 | 停用期间暂停新增记分，历史信息及记分记录继续可查询 |

## 小卖部与购买

| 编号 | 前提与操作 | 预期结果 |
| --- | --- | --- |
| P01 | 甲通过与乙的约定获得积分，在同一空间丙的店铺购买 | 使用甲在该空间的余额支付 |
| P02 | 甲余额 40 分，商品或服务单价 10 分，一次购买 3 份 | 扣除 30 分，余额 10 分；购买记录保存购买时内容、单价 10、数量 3、实际支付 30 分 |
| P03 | 单价 10 分、数量 3 份，买方余额 20 分或负数 | 购买因余额不足无法成立，余额保持原值 |
| P04 | 单价或数量填写为 0、负数或非整数 | 提示修正为正整数，修正前完成购买的条件尚未满足 |
| P05 | 商品或服务保持上架，甲再次发起一笔购买且余额足够 | 形成新的购买记录并按其总价扣分 |
| P06 | 购买已成立，店主随后改价或下架 | 原购买的内容、单价、数量和实际支付积分保持；已成立购买可以继续履行 |
| P07 | 一笔购买的全部商品或服务已经提供，由买方或卖方确认完成 | 标记已完成，记录操作人和时间，通知另一方；确认操作仅改变履行状态 |
| P08 | 一笔单份购买实际支付 20 分，买方或卖方取消；商品现价已变 | 买方获得原支付的 20 分退款，记录标记已取消，原信息及取消经过保留 |
| P09 | 单份购买已经完成，随后买卖任一方取消 | 允许取消并退款，原完成和取消经过均可查询 |
| P10 | 双方重复取消同一笔购买 | 保持一次整笔取消和一次全额退款 |
| P11 | 一次购买 3 份服务、实际支付 30 分，已提供 1 份，随后任意一方取消 | 提供 1 份后购买仍为待完成；取消时整笔标记已取消，向买方退款 30 分，保留购买及取消经过 |
| P12 | 一次购买 3 份服务、实际支付 30 分，全部提供后任意一方确认完成，随后任意一方取消 | 先整笔标记已完成；取消时整笔标记已取消并退款 30 分，完成与取消经过均保留 |

## 退出与退款

| 编号 | 前提与操作 | 预期结果 |
| --- | --- | --- |
| L01 | 甲余额 30 分，持有一笔曾支付 20 分的单份待完成购买；甲退出 | 自动取消并返还 20 分，甲保留 50 分余额，记录注明由退出触发 |
| L02 | 乙作为卖方退出，甲有一笔向乙购买的单份待完成记录 | 购买自动取消，原支付积分返还甲；取消和退款仅执行一次 |
| L03 | 甲退出前一笔购买已完成 | 退出处理保持该笔已完成状态；历史记录保留 |
| L04 | 已退出的甲是历史已完成购买的买方，仍在空间的卖方乙取消该笔购买 | 按原规则退款到甲保留的余额；甲返回后看到更新后的余额和完整历史 |
| L05 | 甲退出后，其一条历史记分被当前成员按原规则撤销 | 回退原记分影响，更新甲保留的余额和历史；甲退出期间暂停新增约定记分的规则继续有效 |
| L06 | 一次购买 3 份服务、实际支付 30 分，已提供 1 份且仍待完成，买方或卖方退出 | 自动整笔取消，向买方退款 30 分且仅退款一次；记录退出原因，成员返回后该笔购买仍为已取消 |

## 重复提交与同时操作

以下场景验证已确认规则在网络重试和同时操作时保持一致。

| 编号 | 前提与操作 | 预期结果 |
| --- | --- | --- |
| C01 | 同一次记分或购买在网络超时后重新提交 | 返回同一次操作的结果，积分和业务记录只产生一次对应变化 |
| C02 | 余额 30 分，同时发起两笔各 20 分的购买 | 至多一笔购买成功，成功时余额为 10 分，另一笔按不足处理 |
| C03 | 成员退出与涉及该成员的新购买同时发生 | 以生效顺序处理；退出生效时参与的待完成购买按退出规则取消，退出后暂停新购买 |
| C04 | 记分撤销、购买退款或退出处理在中途失败后恢复执行 | 业务状态与积分结果保持一致，每个已生效回退或退款仅发生一次，可从历史解释最终余额 |
