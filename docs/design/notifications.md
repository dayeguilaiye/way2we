# 通知模块设计

状态：已采纳，待实现。

## 已确认的目标

首版提供站内通知。产品允许中国大陆与海外用户互相建立约定和互动，并保留接入系统推送及微信小程序等通知渠道的能力；渠道扩展的改动集中在通知相关模块。

## 业务接口

约定、积分、购买等业务模块通过通知模块提供的稳定接口记录事件。事件包含稳定标识、事件类型与版本、接收者、业务资源标识、发生时间，以及生成通知所需的业务数据。

通知模块管理事件到通知的转换、接收者的通知偏好、各渠道所需的内容格式，以及业务资源在各客户端中的打开方式。渠道凭据和模板配置由相应的发送实现管理。

## 数据与处理流程

1. 业务变更与通知事件在同一数据库事务中保存。接口返回成功表示业务数据和事件已持久化。
2. 提交后的处理流程消费事件，生成接收者的站内通知；站内通知以事件和接收者标识去重，并支持查询及标记已读。
3. 通知模块根据启用渠道、用户授权、偏好和可用的设备或订阅信息，生成投递任务。
4. 投递任务独立记录目标、状态、尝试次数和结果；可重试失败按策略重试，终止性失败保留记录以便排查。

首版启用站内通知。处理流程可以作为 Go 应用内的后台工作执行，具体存储选型在后端设计时确定。站内已读状态和渠道投递状态分别管理，业务结果以已提交的业务数据为准。

使用稳定标识消除重复的事件处理和任务创建；外部渠道支持幂等能力时使用其机制，发送超时或结果不明时按该渠道规则处理。该设计的验证范围包括应用重启后的恢复处理。

## 新增渠道时的工作

- 实现渠道发送适配器，处理该渠道的内容映射、授权条件、投递结果和失败分类。
- 接入所需的设备令牌或订阅信息，并维护其有效性及与内部用户的关联。
- 增加用户授权和通知偏好处理，以及必要的客户端 SDK 和权限配置。
- 将通知中的业务资源映射到客户端页面；用户打开资源时，由业务接口校验当前访问权限。
- 在目标地区和设备上验证发送、接收和点击后跳转的行为。

新增渠道的目标改动范围包括通知模块及相关客户端接入。约定、积分和购买模块通过既有接口记录相同的业务事件。新增业务事件类型时，根据该事件的信息需求扩展事件定义和展示内容。

## 实现后的验收要点

- 添加一个验证用的外部渠道实现，通过已有事件触发投递，验证业务模块的调用接口保持稳定。
- 重复处理同一事件时，每位接收者获得一条对应的站内通知。
- 业务事务回滚时，事件也回滚；提交后应用退出时，恢复运行能继续处理事件。
- 渠道发送失败时，站内通知保持可读，已提交的积分和购买结果保持有效。
- 授权失效或用户关闭某渠道时，通知模块依据最新状态选择可用渠道。
