# 首轮实施任务

状态：阶段 3.2 已完成任务拆分。依据[数据模型](../engineering/data-model.md)、[OpenAPI](../../api/openapi.yaml)与[工程规范](../engineering/README.md)推进；T00 工程基础已完成，下一任务为 T01。

每个任务同时交付服务端、Flutter 和对应检查，完成后保留可演示版本。通知事件从第一个空间流程开始写入，后续操作沿用同一入口。T00 已完成，T01—T07 待实施。

## T00 工程基础与共用契约

状态：已完成。实施与验证记录见[工具链与工程基础](../engineering/foundation.md)，运行入口见 [README](../../README.md)。

输入是已确定的[技术栈与主要依赖](../engineering/architecture.md#技术栈与主要依赖)及[工程规范](../engineering/README.md)。T00 将这些要求落实到依赖声明、配置和基础代码中。

建立 `apps/mobile`、`server`、数据库迁移和本地配置，固定工具版本与依赖。Go 提供健康检查、请求编号、结构化日志、统一错误转换及幂等命令执行入口。Flutter 建立主题、路由、会话与网络错误映射，沿用已采纳视觉基准。根目录补齐启动、检查和构建命令。

明确交付：工具链与构建目标记录、`go.mod`／`go.sum`、`pubspec.yaml`／`pubspec.lock`、`analysis_options.yaml`、安全示例配置、统一检查入口，以及贯通两端的一条正常响应和错误响应示例。每项均按已有规范检查。

检查：iOS 与 Android 可启动并访问本地 Go；空测试库可迁移；以模拟接口错误验证字段提示、通用错误和请求编号；OpenAPI 静态检查进入统一检查入口。测试数据库与正式数据库明确隔离。

## T01 邮箱登录与个人外观

端点：`requestEmailCode`、`createSession`、`deleteCurrentSession`、`getMe`、`updateMe`。

实现邮箱规范化、验证码频控与发送适配、原子验证、账号取得和会话撤销。Flutter 提供验证码登录、重新发送、到期反馈和三套主题选择；同邮箱换设备恢复原账号。测试使用可控邮件适配器，实际邮件接入时验证国内及海外邮箱送达。

检查：验证码过期、错误次数、并发验证、重复邮箱注册和结果丢失恢复；正式日志不出现验证码或凭据。邮件供应商及发件域名配置在真实发送前完成。

## T02 空间、邀请与第一条站内通知

依赖：T01。端点：空间创建／列表／成员、邀请创建／预览／接受／同意／查询，通知查询与已读。

实现稳定成员身份，客户端展示本人参与过的空间，支持复制邀请码、从链接取得邀请码后登录并接受。发起邀请视为同意，新人可查看申请进度。接入事件落库、worker 领取与去重、站内通知展示及跳转。

检查：S01—S04、S08；多人全部同意才加入，邀请码只能绑定一人；原成员全部退出后保持等待。重复事件处理与提交后进程重启能够恢复。具备两个真实账号进入同一空间的演示。

## T03 约定、记分与积分明细

依赖：T02。端点：约定 CRUD 范围内的创建／完整更新／查询／版本、记分／撤销／查询、积分明细、近况与首页。

实现约定修订与适用成员、固定正负分值、原值撤销、成员余额与流水。Flutter 完成约定列表、记一笔、撤销、明细和近况刷新。每次记分以服务端提交时的有效约定为准。

检查：A01—A09、C01、C04；相同标识重放一笔记分、不同标识重复使用约定、负余额、修改后按原值撤销，页面超时能核对结果。

## T04 小卖部与购买

依赖：T03。端点：商品创建／编辑／列表／详情、购买创建／列表／详情、操作结果核对。

实现店主编辑与上下架、商品版本、买卖双方和余额校验、购买快照及立即扣分。Flutter 展示小卖部、数量和总价；商品版本变化时展示最新内容，再由用户确认购买。待处理列表只显示本人可处理的交易。

检查：P01—P06、C01、C02；购买多份、同一请求双击／超时重放、不同请求争抢余额、购买自己商品被拒绝，卖方余额保持原值。核对原型中的按钮、表单和错误反馈。

## T05 完成、整笔取消与退款

依赖：T04。端点：`completePurchase`、`cancelPurchase` 及已有通知与记录端点。

实现双方完成、pending／completed 均可取消、按原 paid_points 全额退款。Flutter 首页提供完成／取消按钮，详情保留完整经过，确认面板沿用紧凑标题与正常正文字号。

检查：P07—P12、C04；完成与取消同时执行、双方重复取消、已取消购买再次完成、服务重启恢复。T05 完成后演示两账号“加入 → 约定 → 记分 → 买两份 → 完成 → 取消退款 → 站内通知”的完整流程。

## T06 退出、恢复与权限收尾

依赖：T05。端点：`leaveSpace`、`restoreMembership`，并核验所有空间资源接口。

实现退出事务中的全部待完成购买取消及退款，保留历史和余额；恢复沿用原成员身份与店铺状态。退出后普通业务读取关闭，本人退出结果仍可安全核对。客户端清理当前空间活动状态，显示恢复入口。

检查：S05—S08、L01—L06、C03、C04；双方退出、无人空间、历史买方退款、跨空间资源 ID、退出与新购买竞争、旧响应在切换空间后返回。

## T07 图片、双端适配与运行检查

依赖：T04，可在 T05—T06 完成后集中交付。端点：`createMediaUpload`、`completeMediaUpload`、`getMediaAccess`。

实现私有商品图片上传、实际文件验证、历史图片引用及临时访问。验证三套主题、长内容、大字体、原生返回、键盘及安全区域。完成日志检索、数据库备份恢复和两端构建说明。

检查：上传失败／过期／重试，图片引用与当前权限，旧购买图片保留；真实设备走完整流程，国内与海外网络检查登录、接口和图片。供应商、正式部署地区与备份恢复窗口在真实上线前落实。
