# 前后端接口约定

状态：阶段 3.1 已获用户采纳。适用于 Flutter、Go 与未来小程序。首轮具体端点见 [OpenAPI 契约](../../api/openapi.yaml)和[数据与事务设计](data-model.md)。

## 协议和数据

业务接口使用 HTTPS，路径前缀 `/v1`，JSON 字段使用 `snake_case`。HTTP 状态表达请求结果；成功响应直接返回资源或操作结果，列表返回 `items` 与 `next_cursor`，空列表为 `[]`，末页游标为 `null`。

ID 为不透明字符串。积分和数量使用整数，JSON 整数范围限定在 JavaScript 安全整数范围内；服务端在计算前检查输入、乘积、变化量和最终余额的范围。具体业务上限在对应接口声明。时间统一返回带 `Z` 的 UTC RFC 3339 字符串；显示时区由客户端处理。

列表使用不透明游标，排序包含唯一 ID 作为相同时间下的次级顺序。建议默认每页 20 项、最大 100 项。可选字段、缺省值、空值含义和最大长度逐项写入契约。输入校验由服务端执行，客户端同步校验以便及时提示。

服务端每次收到请求生成新的 `request_id`，通过 `X-Request-ID` 返回；错误响应也携带同一值。每次重试获得新的请求编号，业务意图使用下文的 `Idempotency-Key` 关联。鉴权使用 `Authorization: Bearer …`。

## 错误格式

以下为项目自定义 JSON 契约。示例：余额不足返回 HTTP 409，`Content-Type: application/json`。

```json
{
  "error": {
    "code": "INSUFFICIENT_POINTS",
    "message": "积分不足，请调整数量或稍后再试。",
    "field_errors": []
  },
  "request_id": "req_example_01"
}
```

`code` 是稳定的业务标识。`message` 是安全的简短说明；Flutter 按错误码映射本地提示与操作，未知错误码显示通用提示并保留请求编号。客户端通过结构化字段判断行为。服务端内部原因、SQL、堆栈、凭据和供应商响应保留在受控诊断路径。

字段校验失败返回 HTTP 422：

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "请检查填写内容。",
    "field_errors": [
      {"field": "quantity", "code": "POSITIVE_INTEGER_REQUIRED"}
    ]
  },
  "request_id": "req_example_02"
}
```

`field_errors` 始终为数组，字段路径与请求契约一致。未来需要错误参数时，在对应错误码下声明有类型的字段和展示用途。响应可能来自网关或代理；客户端遇到非 JSON、缺少字段或格式错误时归为协议／网络失败，并采用本地通用提示。

## 状态、错误码与用户反馈

| HTTP | 代码 | 典型情况 | 客户端行为 |
| --- | --- | --- | --- |
| 400 | `INVALID_REQUEST` | JSON 无法解析、缺少必需请求头 | 保留输入，展示请求无法提交；记录诊断编号 |
| 401 | `UNAUTHENTICATED` | 会话无效或到期 | 进入登录；恢复后由用户继续原操作 |
| 401 | `CODE_INVALID_OR_EXPIRED` | 登录验证码无效、过期或已用尽 | 留在验证码页，按间隔重新申请；此公开接口独立于会话到期处理 |
| 403 | `FORBIDDEN` | 当前成员可查看资源，但无权执行操作 | 说明权限不足并刷新可用操作 |
| 403 | `MEMBERSHIP_INACTIVE` | 本人已退出当前空间 | 更新成员状态并返回可访问入口 |
| 404 | `NOT_FOUND` | 资源不存在，或调用者无权知道该资源 | 提示内容不可用 |
| 404 | `OPERATION_NOT_FOUND` | 尚未查到该操作的已提交结果 | 原请求可能仍在执行，沿用原标识继续核对 |
| 409 | `INSUFFICIENT_POINTS` | 购买时最新余额不足 | 保留数量，刷新余额，提示调整 |
| 409 | `ITEM_CHANGED` | 所见商品版本已变化 | 展示最新内容与价格，重新确认购买意图 |
| 409 | `ITEM_UNAVAILABLE` | 商品下架或店主暂停参与 | 刷新商品并关闭购买入口 |
| 409 | `RESOURCE_STATE_CONFLICT` | 对已取消购买执行完成 | 刷新记录并解释当前状态 |
| 409 | `IDEMPOTENCY_KEY_REUSED` | 相同标识提交了不同参数 | 停止自动重试，核对原操作 |
| 409 | `OPERATION_IN_PROGRESS` | 同一操作仍在执行 | 保持核对中，稍后以原标识查询或重试 |
| 409 | `UPLOAD_NOT_READY` | 上传尚未完成或对象暂不可见 | 查看上传结果，准备好后重新发起校验 |
| 422 | `VALIDATION_FAILED` | 数量不是正整数等字段问题 | 在字段旁显示原因，保留表单 |
| 422 | `INVALID_MEDIA` | 实际图片类型、大小或解码结果不合格 | 重新选择合格图片 |
| 429 | `RATE_LIMITED` | 验证码或接口请求过于频繁 | 按 `Retry-After` 提示稍后再试 |
| 500 | `INTERNAL_ERROR` | 未预期错误 | 显示通用提示和请求编号；写操作按原标识核对 |
| 503 | `SERVICE_UNAVAILABLE` | 数据库暂时不可用等 | 保留输入，延迟重试；写操作沿用原标识 |

先识别请求格式与登录身份，在返回受限数据前检查访问权限，再在事务内核验业务状态和输入规则。正常业务拒绝只记录 INFO；系统故障记录 ERROR，详见[运行规范](operations.md)。

## 重复提交与结果不明

记分、购买、撤销、退款、退出等有业务副作用的命令携带 UUID 格式的 `Idempotency-Key`。客户端在用户开始提交一次意图时生成，双击、超时、连接中断和恢复核对沿用同一值。参数已修改或用户明确发起下一笔操作时，生成新值。

服务端按“内部账号 + 操作标识”唯一保存请求指纹与结果。指纹包括操作种类、空间、目标资源和规范化后的业务参数；鉴权凭据及请求编号独立处理。每次调用均重新检查当前权限。

1. 新操作在空间事务中取得资格并执行，成功结果与业务记录、流水、事件一同提交。
2. 相同标识、相同指纹返回已记录结果；新响应有自己的请求编号。若资源后来变化，客户端继续读取其当前状态。
3. 相同标识、不同指纹返回 `IDEMPOTENCY_KEY_REUSED`，业务保持原结果。
4. 同一操作并发到达时，数据库唯一约束与事务锁协调执行；等待超过限时返回 `OPERATION_IN_PROGRESS`。
5. 已鉴权且格式有效的操作，在业务写入前判定余额不足等确定性拒绝，可提交仅含请求指纹及拒绝结果的记录。再次尝试购买属于新意图，生成新标识。
6. 格式、鉴权或访问失败在执行业务前返回；系统故障回滚。提交结果不明时，先核对持久化操作结果，再决定执行，继续使用同一标识。

已提交业务操作的去重标识随其历史保留。拒绝结果首版也持久保留最小指纹和结果，避免清理后旧重试成为新操作。存储及清理策略发生变化时，需要同时更新客户端重试期限和服务端拒绝过期请求的规则。

取消、撤销、完成还有资源状态约束：重复取消只退款一次，重复撤销只回退一次，重复完成返回已完成结果。已完成购买允许取消并退款；已取消购买执行完成则产生状态冲突。不同操作标识也受这些约束保护。

客户端将未确认写操作的标识、参数指纹和必要核对信息保存在当前账号的应用私有存储，恢复前先验证账号及空间。服务端提供按操作标识核对结果的能力，端点在阶段 3.2 定义。一次查询未找到结果时，原请求仍可能正在执行，因此后续提交继续沿用原标识。

网络超时或收到 5xx 时，界面显示“暂未确认结果，正在核对”或提供核对入口。读取可有限次数自动重试；写入的自动重试集中在具备上述幂等规则的路径，使用有限次数、退避和抖动。未联网时保留表单，提交时要求联网。

## 邮箱验证码登录

用户已确认邮箱验证码登录，同一邮箱验证后恢复同一内部账号。验证码提交成功后，服务端原子完成验证码消费、账号取得／建立和会话签发。并发验证受验证码一次性消费及登录身份唯一约束保护。

初始限制：验证码有效期 10 分钟，每份验证码最多尝试 5 次；同邮箱发送间隔至少 60 秒，并按邮箱与来源设置可配置的发送总量限制。重发使先前验证码失效，达到尝试上限后需重新申请。发送接口使用统一反馈保护账号信息，服务端保存验证码的带服务端密钥摘要、有效期和尝试次数。

验证码用于验证邮箱控制权，发送邮件为独立外部调用。发送状态、超时恢复以及邮箱规范化规则见[数据模型](data-model.md)的账号与登录章节。邮箱绑定变更需验证当前账号和新邮箱；首版账号恢复依赖对原邮箱的控制权。

## 契约演进

接口定义同时包含成功、字段错误、权限错误、状态冲突和幂等重放示例。新增响应字段保持旧客户端可解析；客户端忽略未知响应字段，并对未知枚举值采用明确的未知状态。字段删除、含义改变和权限语义改变需要版本及兼容计划。

每项业务功能先更新 OpenAPI，再同时修改 Go、Flutter 和相关契约测试。错误码的含义保持稳定，新情况新增代码。服务端部署先满足新客户端需要的接口，移动端发布验证旧版本客户端仍可工作。
